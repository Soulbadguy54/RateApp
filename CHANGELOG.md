## 21 октября 2026 — ограничение зависаний при первом включении Push ([PR #42](https://github.com/Soulbadguy54/RateApp/pull/42))
- По коду проверен первый opt-in: приглашение появляется после готовности Service Worker; далее браузер может долго ждать `PushManager.subscribe()` (внешняя Push-служба), и только после этого вызывается `PUT /api/push/subscription`. Это два разных источника задержки; без измерений на устройстве невозможно приписать конкретный случай одному из них.
- На `r-app.ru` внешние запросы `/api/health` (200, 364 мс), `/api/push/config` (без cookie — ожидаемый 401, 239 мс), `/sw.js` (200, 319 мс) ответили быстро. Замеры не включают авторизованный PUT или браузерную Push-службу.
- В первом приглашении и настройках профиля отображается текущая стадия подключения; ожидание готовности worker ограничено 8 секундами, браузерной подписки — 20 секундами, записи на сервер — 10 секундами. Ошибки позволяют повторить попытку; уже созданная браузерная подписка используется повторно. После успешного PUT переключатель профиля больше не ожидает дополнительного обновления конфигурации.
- Изменение предложено в PR #42; оно не означает, что новая версия опубликована. Обязательно проверить реальный Android/iOS PWA opt-in после деплоя.

## 21 октября 2026 — hotfix SSH ancestry guard (PR #41)
- После исправления runner checkout GitHub Actions достиг VPS, но принудительный root dispatcher отклонил коммит из main: ограниченный fetch refspec первоначального клона не содержал `origin/main`. На работающем VPS dispatcher исправлен на явный fetch `+refs/heads/main:refs/remotes/origin/main`; проверка ancestry для текущего main прошла. Исходный dispatcher в репозитории исправлен тем же PR. Деплой перезапущен через rerun failed jobs.

## 21 октября 2026 — hotfix автоматического деплоя (PR #40)
- Первый main CI и публикация обоих контейнеров в GHCR успешно прошли, но deploy job остановился до SSH: runner не содержал `deploy/ssh_known_hosts` (не было `actions/checkout` в отдельном job). Добавлен checkout проверенного SHA в deploy job; после merge повторно проверить полный GitHub → GHCR → SSH → VPS. Сайт на VPS оставался работоспособным без прерывания.
