# Игровой Tinder: подготовка без UI и свайпов (24 октября 2026)

## Срез данных на staging
Агрегированная *read-only* проверка `rateapp_stage` для владельца `soulbadguy` 24 октября 2026:
- Общий каталог: **1184** игры.
- Всего `user_games` владельца: **147**, из них **95** со статусом `completed`/`dropped`.
- **20** из оценённых игр имеют одинаковые значения всех четырёх критериев: изолированно это **не доказывает** импорт, но именно эти оценки нельзя без проверки трактовать как независимые оценки сюжета, атмосферы, технологии и геймплея.
- Из всех 147 игр владельца без жанра: **1**, без даты релиза: **2**. Полезно для старта, но актуальные данные могут отличаться от этого снимка.
- У нас нет сохранённых IGDB `themes`, `keywords`, `game_modes`, `similar_games` и проверенных owned-platform библиотек. Для сильных рекомендаций эти данные надо собирать **пакетно** при расширении кандидатов, а не сразу во всей базе.

## Что можно сделать до пользовательского интерфейса
1. **Рассчитать базовый профиль** по завершённым/дропнутым играм, с весом исходной оценки и признаками жанра. Для одинаковых четырёх критериев учитывать только общий балл, не делать выводы о качестве сценария и графики по отдельности.
2. **Проверить качество профиля офлайн**: скрывать, например, 15–20% оценённых игр, строить ранжирование только по остальным, смотреть, насколько высоко поднимаются действительно понравившиеся; повторить несколько случайных разбиений. Не использовать скрытые данные при расчёте.
3. **Подготовить общий список кандидатов** (игры, которых ещё нет в реальных прохождениях / wishlist конкретного пользователя). Не скачивать целиком IGDB; начать с локальных игр и при необходимости ограниченно расширить по `similar_games` и популярным соседним жанрам.
4. **Задать объяснимые причины:** «похоже на высоко оценённую игру X», «часто нравится тебе этот жанр», «неожиданная находка». Не заявлять персональную точность до её проверки.
5. Зафиксировать UX: где раздел расположен, сколько карточек, undo / история свайпов, отсутствие повторов, управление ошибочными свайпами. До решения по UX **не создавать** таблицы `discovery_events`, API `/api/discover` и отдельный UI.

## Неподвижные действия свайпов, согласованные ранее
- **Влево:** нравится — положительный сигнал, но **не** запись в wishlist.
- **Вправо:** не нравится — отрицательный сигнал, не постоянный blacklist.
- **Вверх:** добавить в существующую системную коллекцию ❤️ «Хочу пройти».
- **Вниз:** подробности игры: описание/скриншоты/трейлер/магазины; это не отрицательная оценка.
- Реальные оценки важнее свайпов. Историю свайпов можно пересмотреть и исправить.

## Первая экспериментальная реализация v1 (feature/discovery-v1)

Вход из «Базы игр» → «Для тебя»; показ первой карточки без дополнительной кнопки «начать»; первое открытие включает пятиступенчатую обучалку, дальнейшие — сразу ленту. Кнопка i перезапускает обучение, браузерный Back закрывает режим. Постер с метаданными, раскрываемая панель с уменьшающейся обложкой слева, описанием и ссылками; жесты как согласованы выше. Решения записываются в таблицу events, undo возвращает карточку и отменяет членство wishlist только если его добавил этот swipe. Признаки текущих рекомендаций — жанры, оценки, рейтинг IGDB; `similar_games`, themes, keywords, offline-validation остаются последующими отдельными задачами.

## Уточнение UI для второй итерации (24.10.2026)

После просмотра первой версии владелец изменил направления горизонтальных жестов: **вправо нравится**, **влево не нравится**. Это явный приоритет над исходным списком «Неподвижные действия свайпов» выше; вверх по обложке остаётся «Хочу поиграть». Вместо свайпа вниз по обложке подробности показывает отдельная перетягиваемая вверх стеклянная панель по шеврону. Панель занимают метаданные и рейтинги справа, описания/магазины открываются при достижении порога жеста; неполный жест возвращает её назад, обратный полный сворачивает. Во время открытых деталей нет действий like/dislike/wishlist. Нижние action-кнопки убраны; цветные направляющие появляются кратко. Обучалка — один анимированный экран. Изменения v2 реализуются только в UI, действующие таблицы и рекомендации остаются как в v1. Production не меняется до приёмки.

## Коррекция UX после просмотра v2 (24.10.2026; staging PR)

Владельцем отклонён fullscreen-постер поверх приложения и скрытие bottom-nav. Обновлённое требование: не трогать штатную верхнюю/нижнюю структуру приложения; использовать рабочую площадь внутри «Базы игр» и вписывать постер по ширине целиком без cropping. Нижняя часть — **маленькая полупрозрачная liquid-glass-полоса**, а не серая плашка на половину обложки. Имя/дата/жанр и два рейтинга (справа) находятся именно на ней. При вытягивании вверх за шеврон расширяется только стекло, постер абсолютно независим; короткий жест откатывается, достаточный раскрывается, обратный закрывает.

Оценочный свайп действует только на постере: не нужно двигать всю карточку вслед за пальцем — допустимы небольшое смещение и наклон, а после порога полный красивый уход одной анимацией. Направления по ADR-020. Цветные подписи одновременно плавно появляются на ~2 секунды и пропадают на ~5 секунд, без последовательного моргания. Одноэкранная обучалка должна отрисовываться **после** первой карточки, над ней на размытом стекле, с коротким объяснением и стрелками/пояснениями по бокам. Эти правила заменить любой противоречащий подход в ранних разделах этого файла.

## Строгая геометрия экрана Discovery после третьей визуальной проверки (24.10.2026)

**Постер занимает всю область между верхней (back/i) и штатной нижней панелями** без внутренних рамок, боковых полей, пустого bottom-gap и собственных маленьких «картинок в картинке». Для этого отдельный page-класс `.page--discovery` отключает наследуемые отступы каталога и не изменяет саму навигацию. Полотно игры заполняет stage; оригинальное изображение показывается без обрезки с мягким ambient fill той же обложкой для несовпадающих соотношений сторон. Название, релиз, жанр, IGDB/Rate APP должны быть **на стекле поверх нижней части картинки**, а не за её пределами. Шеврон расположен сверху стеклянного блока, стекло по отдельному vertical drag поднимается до 80% высоты stage; постер не двигается и не уменьшается. Геометрические ограничения E2E сверяют края картинки с реальными top-/bottom-bars.

## Дополнение по визуальному результату (24.10.2026, PR staging)

Последний отзыв: стекло **не может выглядеть отдельной нижней карточкой**. Оно лежит над тем же непрерывным постером, и картинка должна проглядывать через поверхность. Сменить `contain` на `cover` (оригинал может слегка обрезаться сбоку, но не оставляет пустой низ), убрать лишнюю тёмную подложку, значительно ослабить альфу и blur стекла. Свернутая высота вычисляется по фактической высоте контента вместе с шевроном и минимальным запасом, а не по фиксированному `min-height`. Верхние края постера скругляются. Новая точная спецификация имеет приоритет перед упоминаниями `contain`, фиксированной высоты 125–149px и тёмного glass в старых секциях.

## Discovery v6 — актуальные требования к данным и жестам (24.10.2026)

По последней пользовательской проверке: текст и магазины доступны прямо в ответе feed из локальной БД, без сетевых IGDB вызовов при вытягивании стекла. Любое получение игры из IGDB сохраняет все предоставленные полями `fields *` значения в JSONB, а не только минимум данных; ранее сохранённые игры дозаполняются отдельной контролируемой batch-командой. Изображение текущей карточки использует HD-версию `t_1080p` и целиком вписывается по высоте/ширине, не обрезая названия на artwork; единый неотдельный фон из размытого того же изображения поддерживает непрерывность glass. Цветная подпись ↑ у верхней кромки; preview перед wishlist также анимируется. Стекло swipeable по почти всей области (handle/text/ratings/details), но исключает переход по ссылкам и не реагирует на простой tap на тексте. Устаревшие требования о crop и открытии только за шеврон заменены.

## Discovery v7: визуальное уточнение (24.10.2026; актуально на staging)

При `contain` вертикальные пустые участки должны оставаться **под постером**, а не над ним: выравнивание `object-position: center top`, сохраняется тот же мягкий blurred backdrop и жидкое стекло снизу. Обучалка — одно размытие уже отрисованной обложки и надписи прямо на нём, **без** самостоятельной glass-карточки, рамок, плашек с подложкой, декоративного названия бренда и кнопки «Начать». По центру суть раздела, сверху «Хочу поиграть»/список желаемого, слева «Не нравится»/меньше похожих, справа «Нравится»/больше похожих. Закрывается касанием любого участка затемнённого экрана или клавиатурой; через `i` открывается повторно. Остальные элементы и алгоритмы v6 без изменений.

## Discovery v8: отмена blur-extension, реальный размер обложки (24.10.2026; актуальный UX на staging)

В отличие от подхода v6–v7 с заполнением свободной высоты размытой копией, **никакого фонового размытого изображения теперь нет**. Сам постер сохраняет собственный aspect ratio (ограничения `max-width/max-height` без искажения), прижат к верхней панели и скруглён на всех четырёх углах. Высота картинки зависит от формата конкретной игры. Фон под ней — системный цвет интерфейса `var(--bg)`; расстояние до нижнего Liquid Glass может быть любым, в том числе нулевым или отрицательным при перекрытии длинной картинки стеклом. Панель крепится к низу viewport и анимируется отдельно от постера, не вытягивает его за собой; сохраняем её прежние метаданные, раскрытие и gesture. Это уточнение заменяет конфликтующие старые требования про "continuous poster" и "ambient blur". Backend и обучение v7 не меняются.

## Discovery v9: последняя визуальная коррекция (24.10.2026; staging)

Теперь над натуральной скруглённой обложкой 12px отступа от верхней панели. Прежнее разрешение произвольного пустого участка между коротким постером и стеклом отменено: свёрнутая панель всегда доходит верхней кромкой до низа изображения, при слишком высоком постере перекрывает его ровно настолько, чтобы поместить шеврон и метаданные. На смене карт разных форматов панель адаптируется плавным Motion spring, не исчезая вместе с keyed-постером. Тёмная полупрозрачная тонировка повышает читаемость текста; обучалка размывает задний план постепенно (0→7px за ~0,5 секунды) без прежнего сильного скачка. Жесты и данные не меняются.

## Discovery v10: UX-коррекция 25.10.2026 (актуально на staging)

Загрузка и пустая лента имеют точно системный фон. Между картинкой и glass теперь **12px**, столько же, сколько от верхней панели до постера: у высокого постера сохранять это пространство путём ограничения максимальной высоты картинки и отображения всех четырёх углов без искажения. Тонировка стекла заметно мягче v9. На развёрнутой панели постоянны заголовок/рейтинг/платформы и иконки источников (Steam, YouTube и др.) над описанием; прокручивать пальцем можно только сам текст в нижней области, не захватывая раскрытие/сворачивание. Русский перевод IGDB-summary показывается по demand, а при внешнем сбое остаётся помеченный английский оригинал. Горизонтальный свайп с первых пикселей получает короткий наклон как лист, вертикальный идёт прямо; цветное свечение по контуру и центральная подпись быстро появляются и затухают согласно цветам подсказок, не требуя подтверждения.
