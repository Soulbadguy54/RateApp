# Rate APP · палитра интерфейса

**Статус:** выбранная базовая палитра дизайна (25.10.2026; PR #60, staging до визуальной приёмки). [Правила проекта](../AGENTS.md) · [решения](DECISIONS.md) · [контекст](PROJECT_CONTEXT.md).

Единые правила компоновки заголовков, форм, карточек и подтверждений — [UI_DESIGN_GUIDE.md](UI_DESIGN_GUIDE.md). Этот файл отвечает за цветовые роли, а не за независимую верстку каждого экрана.

## Правило для будущих доработок

В приложении не нужно придумывать отдельный цвет для каждого нового действия. Сначала использовать существующую семантическую роль: нейтральная поверхность, зелёное положительное действие, холодное синее отклонение, розовое «Хочу поиграть». Для дизайна возможны более светлые/тёмные версии **одного и того же** оттенка (фон, текст, дымка), но не соседний случайный hue. Цвет иконки и её контекст не обязательно совпадают: системная коллекция Wishlist использует красное emoji ❤️ внутри розовой темы.

## Основные роли и источник

| Роль | Цвет | Токен/использование |
| --- | --- | --- |
| Основной фон | `#0b0d12` | `--bg` (общий `src/styles.css`) |
| Поверхность | `#12151c` и `#181c25` | `--surface` и `--surface-2` |
| Разделители | Белый 8/14% | `--line`, `--line-strong` |
| Основной акцент приложения | `#8cf27d` | `--accent` — интерактивные кнопки/фокус, отдельный от эмоциональных реакций |
| Внешняя база IGDB | `#dfb6ff` / `rgba(218,168,255, …)` | `--igdb-accent`, `--igdb-accent-rgb` — рейтинг IGDB и выбранный слот «База игр / Для тебя»; Rate APP навигация остаётся зелёной |
| «Нравится» / зелёная позитивная реакция | `#92e9ae` | `--palette-like-rgb:146,233,174` — тема коллекций `emerald`, надписи/дымка Discovery |
| «Не нравится» / спокойный отказ | `#8ebaff` | `--palette-dislike-rgb:142,186,255` — тема коллекций `blue`, текст/дымка Discovery |
| «Хочу поиграть» / wishlist | `#ffa2ca` | `--palette-wishlist-rgb:255,162,202` — `rose`, текст/дымка; emoji ❤️ из общей иконки wishlist |
| «Добавить прохождение» / свайп вниз | `#f8d783` | `--palette-playthrough-rgb:248,215,131` — тема коллекции `amber`, подсказки/ярлык/дымка Discovery; только навигация в существующую форму |
| Основной текст | `#f7f7fa` | цвет `:root`, рядом нейтральные ослабленные подписи `--muted` |

**Единственный источник цифровых RGB-значений четырёх направлений:** `:root` в `src/styles.css`. Для CSS текста использовать `rgb(var(--palette-*-rgb))`, для прозрачных градиентов — `rgba(var(--palette-*-rgb), .7)`. Не копировать числовые значения в `DiscoverView.css` или в `collectionModel.ts`. Сами варианты коллекций `rose`, `blue`, `emerald` берут `accent` через `rgb(var(...))`; их `shade`/фон остается прежним. Рендер красного emoji ❤️ предоставляет `WishlistHeart` в `src/components/CollectionAppearance.tsx`.

## Исключения и миграция

Исторически у редактора коллекций остаются *десять* именованных тем: `violet`, `rose`, `blue`, `cyan`, `teal`, `emerald`, `lime`, `amber`, `orange`, `slate`. Это допустимая пользовательская настройка; **не удалять** и не переписывать сохранённые значения `colorScheme`. Со временем можно связать остальные оттенки с общими токенами по мере доработок, но не расширять палитру типичных реакций приложения. Красный цвет не применяется к «Не нравится» — избегаем ассоциации с ошибкой или удалением.

## Перед PR

Если интерфейс вводит цвет: определить роль → проверить этот справочник → использовать существующий CSS-токен → добавить тест значения и контраста по возможности → обновить эту страницу и `CHANGELOG.md` при реальном пересмотре палитры. Не считать документацию в `develop` принятой в production до одобрения владельца.

С 25.10.2026 экспериментальный IGDB-слот нижней навигации использует фиолетовый только для активной иконки/подложки и выделения bubble-вариантов; само меню остаётся нейтральной стеклянной поверхностью той же нижней панели, а не залитым сиреневым прямоугольником. Рейтинг IGDB в Discovery берет те же токены.

### Четвёртый жест Discovery (PR #67)

Вниз = «Добавить прохождение» с янтарным цветом; это не новая категория данных и не команда сохранить. Реакции остаются зелёной, синей и розовой. При наращивании интерфейса брать уже существующие янтарные оттенки через `--palette-playthrough-rgb` и `collectionModel.ts:amber`, не добавлять произвольные жёлтые цвета.


## Верхнее стекло разделов (31.10.2026, staging)

Для шапок использовать уже выбранную тёмно-холодную палитру, не создавать новый оттенок: --header-glass-background = linear-gradient(150deg, rgba(14,19,32,.46), rgba(16,24,41,.43) 52%, rgba(10,17,31,.52)), --header-glass-filter = blur(12px) saturate(120%). Эти параметры **совпадают** с glass-sheet «Для тебя»; материал задаётся в src/styles.css, а числовая типографика/прямоугольная геометрия — в docs/UI_DESIGN_GUIDE.md. Для границы только нижняя rgba(255,255,255,.13), сверху и сбоку контур не рисуется. Основные зелёный и фиолетовый акценты остаются прежними.


## Персональная палитра профиля (01.11.2026, develop/staging)

Шесть выбранных оттенков: violet/rose/blue/teal/amber/coral (новый коралловый #ee8a72). Слева отдельный пункт «Без оттенка», не являющийся новым цветом. **Зелёной свотчи нет**: default означает обычное нейтральное стекло, но никнейм @nickname, подпись и активная капсула нижнего «Профиль» становятся основным зелёным --accent. Иначе эти элементы используют точно выбранный акцент, а другие пункты навигации не перекрашиваются. Общий источник цветовых значений — src/profilePalette.ts; API разрешает те же варианты без изменения схемы БД.
