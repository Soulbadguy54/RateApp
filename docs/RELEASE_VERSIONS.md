# Публичные версии Rate APP — аудит и правила

## Новая нумерация (01.11.2026)

Формат: **YY.MM.NNN**, год и месяц фактического первого production-выпуска пакета, счётчик с 001 в каждом новом месяце. **Один номер = один подтверждённый успешный production deploy всей партии**, а не PR, повтор job, промежуточный staging preview или каждое внесённое изменение. Следующая версия закрепляется на develop до приёмки и production выпуска; на каждом preview не увеличивается. Если до релиза изменился месяц, обновить месяц в номере ещё не выпущенного пакета.

Для первой исторической серии точка отсчёта — первый подтверждённый VPS production release 21 октября 2026. До перехода на VPS Vercel автоматически публиковал production-сборки множества отдельных коммитов. Они не были пакетными релизами и не переводятся задним числом в номера новой линейки. Источник: GitHub Actions [VPS production deployment](https://github.com/Soulbadguy54/RateApp/actions/workflows/vps-deploy.yml). За 21–27 октября обнаружено **12 успешных запусков с разными выпущенными SHA**. Первый failed запуск исключён, повтор одной попытки не учитывается как новая версия.

Публичный реестр — **src/releaseNotes.ts**. В нём первая запись — готовящийся следующий релиз, ниже — подтверждённые прошлые. Значимые изменения из отдельных develop PR дописывать в changes первой записи простыми пользовательскими формулировками; не показывать технические названия, SHA, миграции или PR в UI. При отсутствии крупных изменений оставлять changes пустым, не придумывать пользовательские функции. По завершении подтверждённого production-выпуска закрепить настоящий SHA и job, затем создать следующую запись для новой партии. Перед production соблюдать полный CI и подтверждение владельца согласно AGENTS.md.

**Проверено на 01.11.2026:** запущенная production версия — **26.10.012**, SHA 2b4b61865d74. Подготавливаемая в develop/staging версия — **26.11.001** (Steam, профиль и «Мои ссылки»). Новая версия не считается опубликованной на production до проверенного deployment.
