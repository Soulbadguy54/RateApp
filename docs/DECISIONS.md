# Rate APP — журнал архитектурных и продуктовых решений

**Состояние: 19 октября 2026 года.** Это объяснение уже принятых решений, а не список обещаний. Каждому новому ADR давать номер, дату, статус и ссылку на PR/код. Ссылки ведут в этот же репозиторий.

## ADR-001 · Локальный PK + внешний уникальный ID IGDB (принято)
`games.id` — независимый внутренний первичный ключ, `games.igdb_id` — UNIQUE/index. `user_games`, жанры и алиасы связаны FK с внутренним PK. Это отделяет нашу модель отношений от внешнего провайдера и предотвращает дубликаты. См. `api/models.py` и `api/games_routes.py`.

## ADR-002 · Игра, прохождение и членство в коллекции — разные сущности (принято)
Каталог `games` общий; `user_games` содержит ровно одно пользовательское состояние игры (`user_id + game_id` unique); `collection_games` описывает независимые связи. Wishlist не должен загрязнять «Мои игры», а удаление из коллекции не стирает прохождение. PR #2, #8, #9, #11.

## ADR-003 · Серверная обязательность критериев и дат для завершённых (принято)
Для completed/dropped обязательны платформа, дата, четыре критерия в диапазоне 1–10. Агрегат считается из критериев, валидируется в API и PostgreSQL. Для playing отдельной обязательности даты/платформы **нет**, пока UI не поддерживает явный ввод даты. PR #26, #32, #33.

## ADR-004 · Шаг UI оценки 0,5, точность хранения 0,1 (принято)
Оценки выставляются в четырёх барабанах с шагом 0,5, итог округляется до 0,1 по ROUND_HALF_UP. Старые значения до 0,1 не мигрируются и сохраняются; редактирование предлагает ближайшие 0,5. PR #24, #25, #35.

## ADR-005 · Свежая Rate APP оценка важнее кэша IGDB (принято)
Средняя общественная оценка считается по completed/dropped, один голос/пользователь, кроме демо. При открытии карточки запрашивается лёгкий no-store endpoint, результат сохранения содержит пересчитанный рейтинг, а поздний ответ IGDB не должен заменить свежий агрегат. PR #1, #35.

## ADR-006 · Защищённая «Хочу пройти», но её членство независимо от статуса (принято)
Системный slug `wishlist`, наименование «Хочу пройти», красный ❤️, розовая тема. Настройки системы нельзя редактировать/удалять через пользовательский UI; добавление в неё не уничтожает существующее прохождение. PR #2, #9, #34.

## ADR-007 · Строгая UI + backend + DB-валидация, без выдуманных данных (принято)
Пустое название коллекции/невалидная цветовая схема запрещены. Поля пользовательского ввода ограничены и на UI, и в API. Не присваивать произвольные рейтинги/даты из отсутствующих источников. Импорт идемпотентен, дубликаты разрешаются по IGDB обложкам/ID. PR #23, #26, #28–#33.

## ADR-008 · Мобильная PWA с реальной browser history (принято)
Целевые клиенты — iOS/Android. Десктопный gate, загрузка с recovery, install и обновление PWA, сохранение возврата Back/Swipe после добавления игры и поиска. История браузера — источник истины; не создавать дубли экранов игры после save. PR #16–#23, #35; production blank-screen fix 16 октября.

## ADR-009 · API разнесён по доменам, миграции отдельно от cold start (принято)
FastAPI router для auth, library, collection, games/IGDB, push; общие сервисы. Миграции по Alembic выполняются отдельным контролируемым шагом. `Base.metadata.create_all` и ALTER TABLE **не на старте Vercel функции**. Последующая проверка backend CI обязательна. Аудит 16 октября, `docs/DEPLOYMENT.md`.

## ADR-010 · Секреты и аккаунты не в документации; минимальный экспорт (принято)
Argon2 PIN, HttpOnly Secure cookie, серверное хранение хэша токена, throttling. JSON export только владельца и не заменяет backup БД. Операции с данными других пользователей — лишь по явно авторизованному сценарию. `api/security.py`, `docs/DEPLOYMENT.md`.

## ADR-011 · Один контекст в GitHub и автоматическое сопровождение изменений (принято 19.10.2026)
`AGENTS.md` задаёт правила чтения, `docs/PROJECT_CONTEXT.md` описывает актуальное состояние, `CHANGELOG.md` содержит хронологию, этот файл объясняет причины. Любой PR, меняющий поведение, обновляет соответствующую документацию. GitHub `main` — единый актуализируемый источник; каждый новый чат должен реально прочитать файлы.

## ADR-012 · Docs-only коммиты не вызывают новый build (принято 19.10.2026)
Vercel `vercel.json:ignoreCommand` выполняет `scripts/ignore-docs-build.sh`. Если изменения с последнего успешного деплоя затрагивают только Markdown-документацию, скрипт возвращает 0 (skip); если есть код, изменения неизвестны или предыдущий SHA недоступен — 1 (build). Это **не** отменяет GitHub CI, Vercel audit-записи и возможного подсчёта пропущенной попытки в квоте. Проверять после настройки на docs-only коммите.

## ADR-013 · Не обозначать инфраструктурные рекомендации как реализованные (актуально)
Sentry DSN, PITR/snapshot, branch protection, production Alembic baseline — остаются операционными пунктами, пока не проверены независимо. Подробнее `docs/stability-audit-2026-10-16.md`.

## ADR-014 · Выделенный VPS, GitHub Actions и offsite pg_dump (план от 21.10.2026)

Целевое окружение: Caddy, FastAPI и PostgreSQL 18 на VPS, Docker-образы с тегом Git SHA собираются в GitHub Actions после успешного CI. Регулярный деплой по ограниченному SSH-ключу не расходует Gateway. Условие активации: отдельно проверенный первый релиз, внешние секреты и защита ветки. Перед миграциями — проверенная резервная копия, без автоматического отката схемы. Резервные копии — независимый systemd timer + pg_dump + прямой rclone Drive remote Google Drive (без отдельного шифрования, ADR-015) и проверка восстановления. Вход по SSH-паролю остаётся разрешённым по желанию владельца с дополнительной защитой. CI-аккаунт получает только ключ с принудительным SSH-командным обработчиком; отдельная root-команда проверяет, что SHA является предком актуальной main. **Статус:** production развёрнут и проверен на VPS 21.10.2026. См. [VPS_MIGRATION](VPS_MIGRATION.md).

## ADR-015 · Обычные бэкапы Google Drive без дополнительного шифрования (принято 21.10.2026, PR #39)
Владелец сознательно выбрал отказ от `rclone crypt` ради упрощения небольшого личного сервиса. Ежедневные PostgreSQL custom-format дампы сохраняются напрямую в приватный Google Drive через OAuth с разрешением `drive.file`; upload проверяется checksum, восстановление тестируется отдельно. Дамп включает email, хэши PIN, сведения о сессиях и другие данные аккаунтов, поэтому папку не публиковать. Вернуться к дополнительному шифрованию при изменении требований.

## ADR-016 · Задача завершается только после проверенного релиза (принято 21.10.2026)

По умолчанию завершением доработки Rate APP считается успешная доставка в production, а не только PR, зелёные тесты или merge. Агент должен самостоятельно завершить последовательность PR CI → merge → main CI → VPS deployment → production smoke с проверкой SHA версии, устраняя обнаруженные ошибки без повторной просьбы владельца. Исключения: явный PR-only режим, обязательное ревью/разрешение, риск необратимых действий, отсутствующие внешние доступы или проверки на реальном устройстве; в этих случаях фиксировать конкретный блокер. Подробный регламент: [AGENTS.md](../AGENTS.md) и [DEPLOYMENT.md](DEPLOYMENT.md).

## ADR-017 · Отдельный staging на общем VPS (24.10.2026, PR #44)

Решение: `dev.r-app.ru` обслуживается тем же Caddy/VPS, но отдельными frontend/API-контейнерами и отдельной PostgreSQL-базой `rateapp_stage` с **несуперпользовательской** ролью `rateapp_stage` и отдельным паролем. Тестовый API не получает production DB password, cron secret и VAPID-ключи. Production использует только `rateapp` и релизы `main`.

Тестовые данные берутся из проверенного snapshot production в момент первоначального bootstrap; оставляется `soulbadguy` с исходным Argon2 PIN-хэшем и игровой библиотекой/коллекциями, но без существующих сессий, других аккаунтов, login throttle и push-подписок. Bootstrap сохраняет оба дампа до операции и **никогда не меняет production-базу**. Повторный bootstrap автоматически не перезаписывает накопленные staging-данные.

Регистрация запрещена серверной переменной окружения, отдельно от frontend. Сайт не ограничивается IP: личные данные закрыты стандартной авторизацией; публичные статические файлы и `/api/health` не считаются приватными. Домен отмечен `TEST` и `X-Robots-Tag: noindex`. Действующие cookie не копируются; cookie остаётся host-only.

CI запускается для `develop` и `main`. `develop` после успешного CI публикует отдельные stage-образы; привилегированный SSH-dispatcher из проверенного `main` допускает только текущий commit `develop` и использует compose/scripts из `main`, не выполняет скрипты из feature-ветки как root. Новые функции тестируются на staging до принятия решения о релизе на `main`.

Предварительные условия: полный CI для PR; успешный `main` deploy/production smoke; безопасный staging bootstrap и подтверждённый `dev.r-app.ru` smoke. Контур не считать готовым до фактической проверки HTTPS и входа владельца.

## ADR-018 · Возрастной lazy-TTL и единая IGDB-очередь (24.10.2026, проект для staging)

IGDB разрешает локальное кэширование. Вместо полного периодического обновления каталога запросы осуществляются по требованию: у игр до 30 дней от релиза — 7 дней, а у игр старше 5 лет — 365 дней. При просмотре деталей устаревшие каталожные поля обновляются после ответа пользователю. Ошибка внешнего API не повреждает старый кэш. Сроки настраиваются по фактической динамике данных, без удаления старых пользовательских оценок.

Все маршруты используют один backend-коннектор с Twitch OAuth, bounded priority queue, фиксированным интервалом между запросами, ограниченными повторами 429. Известны два экземпляра FastAPI, поэтому каждому выделен ~1.33 req/s: суммарно обычная пиковая скорость меньше внешнего лимита 4 req/s. Межпроцессная гарантированная координация при увеличении количества экземпляров — отдельное последующее решение. Tinder использует этот же шлюз позднее, но его пользовательские действия и экран пока не реализованы. См. [IGDB_CACHE_POLICY](IGDB_CACHE_POLICY.md) и [DISCOVERY_PREP](DISCOVERY_PREP.md).

## ADR-019 · Discovery v1: локальный персональный feed и обратимые действия (24.10.2026; staging до приёмки)

Для первой итерации персональные рекомендации выбираются только из кешированных игр, без IGDB-запроса на свайп. Жанровые предпочтения вычисляются из пользовательских completed/dropped оценок с большим весом, чем разовые likes/dislikes, и дополняются внешним рейтингом/популярностью и детерминированным компонентом поиска нового. Одно событие на игру пользователя хранится в `discovery_feedback`; его отмена удаляет событие и только wishlist-членство, созданное этим действием. Жесты: влево like, вправо dislike, вверх wishlist, вниз подробности. `develop` → staging, до пользовательской приёмки не выпускать на `main`. В будущем проверить ранжирование на отложенных оценках и расширение общего каталога пакетными IGDB-запросами.

## ADR-020 · Discovery UI v2: full-bleed постер + pull-up sheet, переназначение жестов (24.10.2026; staging)

По уточнённому требованию владельца горизонтальные свайпы **переопределены**: влево dislike, вправо like, вверх wishlist. Это изменение UI-контракта ADR-019; серверные значения `like`/`dislike`/`wishlist` сохраняются, исторические события не переписываются. Свайпы делаются на самой обложке, без постоянных кнопок. Плавающая glass-панель раскрывается отдельным шевроном *вверх* и закрывается обратным жестом с spring/snap, а в раскрытом положении блокирует действия свайпов для защиты от случайного выбора. Рейтинги размещены справа, яркие подсказки мигают с интервалами, обучение умещается в один кадр. На staging тестируются реальные жесты Android/iOS перед выпуском на main; сервер и продовая база не меняются.

## ADR-021 · Discovery встроен в app shell, стекло и обложка независимы (24.10.2026; staging)

После пользовательской приёмки v2 выяснилось, что её полноэкранный режим, скрытая навигация, растянутый постер, крупная матовая панель и гирлянда подсказок не соответствуют UX. Решение v2 о собственном fullscreen app-shell **отменено**, bottom nav и layout приложения сохраняются. Исходное изображение не обрезается: contain и мягкий blurred backdrop. Метаданные/рейтинги лежат в маленьком полупрозрачном стекле; drag шеврона влияет только на sheet, drag постера влияет только на положительное/отрицательное/ wishlist решение и минимальный tilt, а finish анимирует один уход. Цветные направления проявляются совместно с длительными паузами; tutorial существует поверх загруженной первой игры. Сохраняем направления из ADR-020: право like, лево dislike, вверх wishlist. Поставляется и проверяется только на `develop`/staging до разрешения main.

## ADR-022 · Discovery cover edge-to-edge, стекло — overlay 80% (24.10.2026; staging)

Слова «всё пространство между верхней и нижней панелями» считаются **точной геометрической спецификацией**, а не желательным приближением. В предыдущем UI полноразмерность была потеряна из-за общих отступов `.page` и двойного вычитания высоты в `.discover-screen`. Теперь `.page--discovery` снимает собственные поля и нижний зазор, оставляя в неприкосновенности навигационные панели. Stage/poster совпадают по геометрии со свободной областью viewport; оригинальный постер не искажается и не обрезается (`contain` + фон из той же обложки). Небольшое liquid glass с шевроном и метаданными располагается поверх постера и по отдельному жесту расширяется до 80% его высоты. Поскольку постер независим от шеврона, его размеры и положение при раскрытии не изменяются. Реальная мобильная геометрия проверяется E2E с допуском 2px. Эксперимент только на develop/staging до пользовательской приёмки.

## ADR-023 · Discovery: непрерывный постер под прозрачным liquid glass (24.10.2026; staging)

При визуальной проверке v4 выяснилось, что `contain` оставляет снизу только тёмный ambient backdrop, отчего метаданные выглядят вторым независимым блоком, хотя их DOM расположен поверх постера. Для основного экрана рекомендаций приоритетнее **непрерывность изображения за стеклом**: использовать `object-fit:cover` с сохранением пропорций и контролируемым crop по краям, убрать дублированный ambient-слой, ослабить tint и `backdrop-filter` стекла. Высота нижней полосы определяется реальным размером текстово-рейтинговой группы через ResizeObserver, а не заранее назначенным пиксельным диапазоном; верхние углы постера закругляются. Критерии проверяются мобильным E2E. Прежние решения ADR-021/022 о `contain` заменяются именно в UI Discovery. Staging до приёмки владельца, production без изменений.

## ADR-024 · IGDB Game snapshot хранить целиком, Discovery без сетевого запроса при раскрытии (24.10.2026; staging)

Новый контракт: при внешнем поиске сохранять весь **возвращённый** `games` JSON в nullable `igdb_payload JSONB`, а не выбрасывать поля, которые текущий UI ещё не использует. Query включает `fields *` плюс понятные expansions для пользовательских деталей; связанные endpoint-объекты за пределами ответа API не загружаются без отдельного задания. Структурированные поля `games` и `details_json` используются как быстрый проекционный кэш для поиска/отображения. Раскрытие Discovery — синхронное действие над данными первоначального feed, а `/api/games/{id}/details` читает исключительно локальный PostgreSQL. Для исторических `igdb_payload IS NULL` — ограниченный ручной backfill; никаких массовых IGDB запросов из UI. Соблюдать суммарный глобальный IGDB лимит и поочерёдные внешние запросы staging/production.

UI выбор: приоритет сохранения целого названия/надписей на постере над crop: `contain` для HD переднего постера + размытое, светлое background fill в том же холсте. Это пересматривает ADR-023 `cover` лишь для визуального слоя, не возвращая отдельную нижнюю плашку. Подсказка у верхнего края, up-gesture получает небольшой preview tilt/scale/y, стекло реагирует на swipe из любой точки кроме внешних ссылок (tap переключает только шеврон).

## ADR-025 · Discovery: сверху полная обложка, обучение только размытием и текстом (24.10.2026; staging)

После приёмки v6 выбрано `object-fit:contain; object-position:center top` вместо вертикального центрирования: при неполной высоте постера ambient blur остаётся преимущественно **снизу**, под стеклом, а изображение не обрезается. Изменение касается только Discovery, не миниатюр каталога.

Обучающий экран должен сохранять первую игру под размытием и исключить собственную визуальную карточку, декоративные рамки и отдельную CTA-кнопку. Оставить только центральное описание назначения рекомендаций и три направленные текстовые подсказки с последствиями жестов; закрывать любое касание overlay. Невидимая доступная кнопка на всю площадь сохраняет keyboard/screen reader доступ без визуального UI; повторный вызов через `i`. Предыдущие детализированные style-решения заменяются этим в Discovery, остальные жесты и стекло неизменны. До приёмки `main` не обновлять.

## ADR-026 · Discovery: натуральный постер вместо заполнения всей высоты (24.10.2026; staging, заменяет часть ADR-023/024/025)

Размер изображения **не должен повторять размер всей области Discovery**. Вписать картинку целиком с сохранением пропорций, ограничить реальными границами viewport, прижать к верхней панели и скруглить все четыре угла. Не создавать декоративную размытую копию, заполняющую оставшуюся высоту. Пустота между нижним краем короткой обложки и стеклом — допустима и окрашена `var(--bg)`, в том числе во время смены игр. Стеклянная панель — независимый нижний слой, не дочерний элемент трансформируемой обложки; может перекрывать длинный постер при открытии. Старые указания о continuous blurred image background отменены только для Discovery. Проверять на разных соотношениях сторон, без влияния на мобильную навигацию и другие типы карточек. Production не обновлять до пользовательской приёмки staging.

## ADR-027 · Привязка свёрнутой панели к высоте постера, тёмное стекло и мягкий blur обучения (24.10.2026; staging)

Владелец отменил произвольный зазор между обложкой и нижним стеклом из ADR-026. Оставляем 12px между верхней навигацией и постером, но верхнюю грань свёрнутого стекла рассчитываем по **фактической** нижней границе видимого изображения. Для высоких картинок приоритет у минимально читаемого блока названия/оценок: он может перекрыть низ постера. Для широких стекло достраивает пространство до нижней навигации. При смене игр непрерывный (не keyed) слой стекла пружинит между положениями; раскрытие по прежнему показывает не меньше 80% рабочей области. Тонировка тёмно-синяя для белого текста, не непрозрачная заливка. Обучающий overlay анимирует реальный CSS backdrop-filter от 0 до 7px вместо мгновенного 17px. Проверять Chromium/WebKit и обложки 3:2 / 2:1. Только staging до принятия.

## ADR-028 · Независимая прокрутка описания, бережная локализация и обратная связь свайпа (25.10.2026; staging)

Отказаться от перехвата прокрутки всего glass: вертикальные touch/scroll внутри нижнего описания **не закрывают** раскрытую панель. Фиксированные метаданные, платформы и компактные внешние иконки располагаются до описания; скролл доступен только самому тексту. Верхний/нижний отступ относительно обложки одинаков — по 12px, без искажения пропорций. При конфликте высоты обложки и видимой панели уменьшать изображение, а не скрывать блок действий. Подложка загрузки равна цвету интерфейса, стекло меньше тонировано.

Поскольку IGDB отдаёт summary/storyline преимущественно на английском, а UI русскоязычен, локализовать **только открываемое описание**, без отправки данных аккаунта внешнему переводу. Для публичного текста используется MyMemory в пределах документированных сегментов (не гарантируется SLA/квота). Отдавать настоящий машинный перевод на русском или явно обозначенный исходный английский fallback; никогда не выдавать автоматический перевод за гарантированный. Запрашивать на demand, кешировать успех. Свайпы получают ранний небольшой наклон (только горизонтально — как перелистывание) и краткий directional glow, не отдельный confirm step. Повторять тесты iOS/Android; production ждёт одобрения владельца.

## ADR-029 · Discovery: направленный flick и долговечная пара EN/RU (25.10.2026, staging, PR #56)

Нижняя панель завершается по доле расстояния либо по скорости жеста последних ~110мс с минимумом 50px. Длинная медленная тяга и tap шеврона сохранены; движение пальца внутри описания не закрывает стекло. Цветной контур включён вокруг рабочей области Discovery с верхним header, но исключает общую нижнюю навигацию, и задерживается поверх следующей карточки на 550мс до 700мс fade.

IGDB — источник исходного английского текста, MyMemory — самостоятельный необязательный сервис RU, с квотой/отказами. Сохранять оба варианта в games.details_json с меткой исходного английского; изменение оригинала инвалидирует только перевод. API предпочитает проверенный RU и сохраняет доступ к EN/RU для будущей локализации, но без перевода возвращает помеченный английский текст. Перевод по demand, только публичный текст, не пользовательские данные. Новый UX выпускается в develop/staging до пользовательской приёмки, не в main.

## ADR-030 · Discovery: edge fog, непрерывный pan и преддекодирование обложек (25.10.2026, staging, PR #57)

Вместо рамки и свечения по border — рассеянная дымка на физических краях рабочей области с вырезанной глобальной нижней навигацией. Эффект не перехватывает события, цвет и центральную подпись предыдущих жестов сохраняем. Горизонтальный pan при непрерывном движении вправо-влево не должен переключать точку вращения, вводить мёртвую зону или фиксировать перемещение на малом пороге; исход одной попытки определяется только при отпускании пальца.

Не загружать увеличенную копию постера без необходимости: уже кэшируемой высокоплотной версии IGDB достаточно для телефона. Декодировать текущий и ближайшие постеры до свайпов по возможности; при медленной сети не показывать рывком неполную картинку, вместо этого использовать ненавязчивый градиентный плейсхолдер и fade/blur reveal. Не блокировать смену карточки ожиданием CDN, ограничить память и поддержать fallback при ошибке. Фича остаётся на develop/staging до одобрения владельца; main/production не менять автоматически.

PR: https://github.com/Soulbadguy54/RateApp/pull/57

## ADR-031 · Семантическая палитра и последовательное появление обучения (25.10.2026, staging, PR #60)

Для часто встречающихся взаимодействий оставить нейтральную основу плюс три уже существующие цветовые семьи: зелёная `like` (emerald коллекций), холодная синяя `dislike` (blue), розовая wishlist (`rose`). Системное ❤️ остаётся красным emoji и обозначает именно коллекцию, не отдельный цвет темы. Не вводить новый оттенок для каждого экрана: подробные исходные значения, контекст и исключения опубликованы в `docs/COLOR_PALETTE.md`, машинный источник — глобальные переменные `src/styles.css`. Существующие дополнительные темы коллекций не удалять и старые пользовательские данные не мигрировать.

Зависимые от картинки подписи размещать по фактической геометрии изображения, измеряемой ResizeObserver, а не по ширине экрана. У обучения сначала должен начаться и преимущественно завершиться blur-переход, затем появиться читаемый текст; в reduced motion сразу показывать конечное состояние. Дымка по краям всего экрана остаётся независимой от положения постера. Публиковать в staging до пользовательской приёмки.
